# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** разработка серверной части платформы Smart Money Concepts для сбора, хранения и синхронизации рыночных данных.

**Автор:** Алексеев Андрей.

**Вклад автора:** разработка backend-части приложения, включая получение котировок и экономических событий, хранение истории и API для интерфейса и аналитических модулей. Серверная часть также предоставляет данные для просмотра прошлых периодов и проверки стратегий. Интерфейс, SMC-разметка и модели машинного обучения разрабатываются другими участниками команды.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

- [QuantConnect LEAN](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting) позволяет подключать рыночные данные и проверять алгоритмы на истории. По задачам серверной обработки это наиболее близкий аналог. Для использования в нашем проекте потребуется добавить собственные форматы SMC-разметки и пояснений к сигналам.

- [TradingView](https://www.tradingview.com/support/solutions/43000562362-what-are-strategies-backtesting-and-forward-testing/) предоставляет графики, язык Pine Script и тестирование стратегий. Режим [Bar Replay](https://www.tradingview.com/support/solutions/43000474024-how-do-i-turn-bar-replay-on/) позволяет последовательно просматривать прошлые изменения цены. Этот сценарий полезен для проекта, но обмен данными между нашими серверными модулями нужно будет реализовать самостоятельно.

- [TrendSpider](https://trendspider.com/product/strategy-development-and-backtesting-tools/) позволяет задавать правила стратегии, проверять их на истории и сравнивать результаты. Для проекта полезен подход к организации таких проверок. Открытые материалы не дают достаточно сведений о внутреннем хранении данных, поэтому эта часть продукта в сравнении не оценивается.

### Косвенные аналоги

- [TimescaleDB](https://docs.timescale.com/) является расширением PostgreSQL для работы с временными рядами. Его можно использовать для хранения свечей и расчёта значений за выбранные периоды. Получение котировок и связь с аналитическими модулями нужно организовать отдельно.

- [FRED API](https://fred.stlouisfed.org/docs/api/fred/) предоставляет макроэкономические ряды, даты публикаций и сведения об изменениях показателей. Он решает часть задачи получения данных. Связь этих записей с котировками и сигналами должна обеспечивать серверная часть проекта.

### Выводы по сравнению аналогов

Рассмотренные платформы уже позволяют получать данные и проверять стратегии на истории. При разработке можно опираться на разделение источников и алгоритмов в LEAN, пошаговый просмотр графика в TradingView и сравнение результатов в TrendSpider.

## 4. Итоги

**Итоговая тема ВКР:** разработка серверной части платформы Smart Money Concepts для сбора, хранения и синхронизации рыночных данных.

**УДК для тезиса:** 004.65 (организация баз данных). Окончательный индекс нужно согласовать с научным руководителем.

**Ключевые слова:** backend; рыночные данные; временные ряды; потоковая обработка; API; экономический календарь; Smart Money Concepts; replay; бэктестинг.

### Актуальность исследования

Для анализа рынка команда использует котировки, экономические новости и результаты работы алгоритмов. Эти данные поступают в разное время. Свечи обновляются в течение торгов, новости выходят по расписанию, а опубликованные экономические показатели могут позднее исправляться. Сервер должен учитывать эти различия, чтобы график и аналитические модули работали с согласованной информацией.

Особенно заметна эта проблема при проверке стратегии на истории. Например, экономический показатель был опубликован утром, а исправлен через несколько дней. Если при расчёте за утро использовать исправленное значение, результат будет учитывать сведения, которых тогда ещё не было. Работа [1] помогает определить правила обработки таких записей. Исследования [5] и [10] показывают значение экономических публикаций для валютного рынка, а работа [4] описывает риски оценки стратегии по историческим тестам.

Готовые платформы предоставляют графики и тестеры, но для совместной работы модулей нашего проекта требуется собственная серверная часть. Она должна сохранять историю изменений, находить пропуски и выдавать данные за нужный момент времени. Подходы к хранению и обработке таких данных рассмотрены в работах [6], [7], [8] и [9]. Результатом станет основа для проверки торговых идей, в которой можно установить, какие данные использовались при каждом расчёте.

### Цель исследования

Разработать серверную часть, которая получает и хранит котировки и экономические события, передаёт их интерфейсу и аналитическим модулям и позволяет повторять расчёты на исторических данных.

### Задачи исследования

1. Выбрать источники котировок и экономических событий. Проверить наличие истории по XAUUSD, EURUSD и GBPUSD и условия доступа к ней.
2. Спроектировать базу данных для свечей, новостей, SMC-разметки и торговых сигналов.
3. Определить правила хранения времени события, времени получения записи и последующих изменений.
4. Реализовать загрузку и проверку данных, удаление повторов и поиск пропусков.
5. Разработать API для получения истории по инструменту, таймфрейму и выбранному периоду.
6. Организовать обмен данными с модулем SMC-разметки и сохранить результаты его работы вместе с версией алгоритма.
7. Реализовать выдачу данных для текущего графика, просмотра прошлых периодов и бэктестинга. Сохранять настройки каждого расчёта.
8. Проверить работу при задержках, пропусках и исправлении записей. Убедиться, что исторические расчёты не используют будущие данные и дают одинаковый результат при повторном запуске.

### Датасеты и сервисы

1. [OANDA v20 API](https://developer.oanda.com/rest-live-v20/introduction/). Кандидат на исторические и текущие цены валютных пар. Нужны аккаунт и токен. Требуется проверить доступность XAUUSD и совместимость истории с текущими котировками.
2. [Dukascopy API](https://www.dukascopy.com/trading-tools/api/documentation). Альтернативные котировки и свечи, в том числе для контроля полноты истории. Проверить разрешённый объём выгрузки, точность меток времени и условия использования.
3. [FRED API](https://fred.stlouisfed.org/docs/api/fred/). Макроэкономические временные ряды, расписание публикаций и даты пересмотра. Нужно учитывать время выхода и исправления показателей. Для полного календаря потребуется дополнительный источник.
4. [Forex Factory Calendar](https://www.forexfactory.com/calendar). Ориентир по составу полей и фильтров экономического календаря. Не считать публичную страницу готовым API или лицензированной исторической выгрузкой.
5. Собственный набор команды. SMC-объекты, журнал сигналов, версии правил, параметры прогонов и контрольные выборки. Данные появятся по мере разработки. Для каждой записи нужно сохранять её источник и версию алгоритма.
